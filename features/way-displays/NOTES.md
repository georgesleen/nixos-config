# way-displays

## Workarounds

- `features/way-displays/home.nix` picker lid check globs `/proc/acpi/button/lid/*/state`: the Framework's lid is `LID0`, the T480s's was `LID`. A hard-coded `LID` path read "open" on the Framework and left eDP-1 lit with the lid shut (2026-10-21, resume 19:06:36, re-enabled 19:06:46).
- `features/way-displays/workspace-plan.sh`: moves a workspace with focus+move because sway IPC criteria don't match workspaces, only window containers.
- `features/way-displays/home.nix` replaced kanshi plus a stack of lid and layout scripts on 2026-10-22. way-displays (1.15.0 in the pinned nixpkgs, so the 1.x `NAME_DESC` list schema, not 2.0's keyed maps) watches the lid itself and disables `eDP*` while it is shut, and arranges active outputs in a row from `0,0`. That row origin is load-bearing for Proton: with the only active output at `x=1920`, Satisfactory under Proton Experimental confined the XWayland pointer to `x<=1919`, so it moved vertically but stuck at the right edge; moving the output to `0,0` fixed it and moving it back reproduced it (2026-10-21). Kanshi could not see the lid, and the bindswitch, reconcile, saved-layout and `&&`-ordering layers that compensated each failed in turn. Runtime picker and swap changes use `way-displays -s/-d` and last until the daemon restarts.
- `features/way-displays/home.nix` `display-changed.service`: `display-events.service` starts this oneshot on every sway `output` IPC event (systemd coalesces the starts). way-displays' `CALLBACK_CMD` cannot drive it: it fires only after way-displays applies a change, never on a departure or on an arrival where sway re-applies its stored output state, so the hook missed those and awww kept a black-filled eDP-1. It re-pins workspaces from `display-mode.sh layout`, then pokes `wallpaper-refresh.service` because awww resets a re-added output to black.
- `features/way-displays/home.nix` `display-changed.service` restarts waybar, because waybar disables `sway/workspaces` permanently (no retry) if an IPC subscribe loses the race with output churn. Symptom is a bar with every module except the workspace numbers after a dock/resume; the external can also come back on a different connector (DP-3 to DP-4), which widens the race.
- `features/way-displays/home.nix` Duplicate: sway has no output mirroring (`Invalid output subcommand: mirror.`), so the picker runs `wl-mirror --fullscreen-output <ext> eDP-1` as the transient user unit `display-mirror`, which every other choice stops. The mirror window sits alone on workspace `mirror` on the external, and `display-changed` keeps every workspace on eDP-1 while the unit runs. way-displays cannot position outputs apart, so `display-changed` confines pointers and touchpads with `input map_to_output eDP-1` while the unit runs and resets them to `*` otherwise. With the lid closed eDP-1 is disabled and the picker refuses Duplicate.
